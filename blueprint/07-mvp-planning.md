# Step 7 — MVP Planning

## Overview

MVP planning is the step where you define the smallest testable version of your product or service that delivers real value to one specific customer. The MVP is not a prototype. It is a real, usable version of the solution that allows you to test your core assumption: that the customer values the outcome enough to pay for it.

In AI businesses, the MVP often starts more manually than expected. A "Wizard of Oz" approach — where a human performs the AI tasks behind the scenes — is a valid and often superior strategy for early validation. Automation comes after you have proven that the workflow produces value.

## Key Questions to Answer

- What is the single most important thing the MVP must do?
- What can be done manually in the first version to test before automating?
- What is the target user experience for the first 5 minutes of use?
- What does a successful MVP look like? How will you measure it?
- What is the minimum technical build required to deliver the core value?
- What is explicitly out of scope for the MVP?

## Core Activities

1. **Identify the core workflow**: Map the 3–5 steps a user takes to go from problem to value. The MVP must cover the critical path, nothing more.
2. **Decide what to automate vs. do manually**: List every step in the workflow and decide whether it should be automated in the MVP or done manually by the builder.
3. **Define success criteria**: Write down what would prove that the MVP delivered value. Use observable metrics, not opinions.
4. **Write the feature list**: List the 3 core features the MVP must have. Explicitly reject everything else.
5. **Plan the concierge element**: Identify the manual steps that will be performed by the builder in the early version to reduce build time.
6. **Define the timeline**: Set a deadline for the MVP. An MVP that takes more than 4–6 weeks to build is probably overscoped.
7. **Identify the first target user**: Name a specific person or organization who will be the first user of the MVP.

## Common Mistakes

- **Building too much before talking to users**: An MVP built over months without user input is a guess. Build in weeks and test.
- **Automating before validating manually**: Automation is expensive to build and hard to change. Validate the workflow value manually first.
- **Not defining done criteria**: Without measurable success criteria, the MVP never feels ready, and scope creeps indefinitely.
- **Building an MVP for an undefined user**: "Everyone who needs AI" is not a user. Name one specific person in one specific role.
- **Confusing a prototype with an MVP**: A prototype demonstrates a concept. An MVP delivers real value in a real context to a real user.

## Deliverables

- **MVP feature list**: A maximum of 3 core features with brief rationale for each.
- **Manual concierge plan**: A description of what the builder will do manually in the first version.
- **Out-of-scope list**: An explicit list of features and capabilities that are not in the MVP.
- **MVP success criteria**: Measurable outcomes that define whether the MVP succeeded.
- **Timeline**: A target date for completing the MVP and delivering it to the first user.
- **First target user**: A named or clearly described person or organization who will use the MVP.
