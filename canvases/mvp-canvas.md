# AI MVP Canvas

## Purpose

The AI MVP Canvas defines the smallest useful version of your AI product or service. It forces you to separate the core workflow from enhancements, decide what to automate versus do manually, and set a clear definition of done.

Use this canvas during Step 7 (MVP Planning). The purpose is not to describe the full product vision — it is to define the minimum version that delivers real value to one real user and allows you to test your core hypothesis.

An MVP is validated when a real user uses it in a real context and reports that it solved their problem. A demo is not validation.

## How to Use

1. Complete every section before writing a single line of code.
2. Review the out-of-scope list — if it is empty, the MVP is overscoped.
3. Name a specific first user, not a persona or a segment.
4. Set the timeline for delivery and hold to it.

---

## Canvas Template

| Section | Your Definition |
|---|---|
| **Problem** | The one problem this MVP solves. One sentence. |
| **User** | The specific person or organization who will use this MVP first. |
| **Core Workflow** | The 3–5 steps the user takes to go from problem to value. |
| **Must-Have Features** | Maximum 3 features. These are non-negotiable for the MVP. |
| **Manual Parts** | Steps in the workflow that will be done manually by the builder in v1. |
| **Automated Parts** | Steps in the workflow that will be automated in v1. |
| **Data Sources** | Where does the data come from? What format? How is it accessed? |
| **Integrations** | Which external services must the MVP connect to? |
| **Success Metric** | How will you know the MVP worked? One observable, measurable outcome. |
| **Timeline** | Target date for delivering the MVP to the first user. |
| **Out-of-Scope Items** | Features, integrations, and capabilities explicitly NOT in the MVP. |

---

## MVP Scope Check

Before starting to build:

- [ ] The MVP has no more than 3 must-have features
- [ ] At least one significant step is done manually to reduce build time
- [ ] A specific first user is identified, not a segment
- [ ] The success metric is observable without surveying users
- [ ] The out-of-scope list is longer than the in-scope list
- [ ] The timeline is 4 weeks or less
