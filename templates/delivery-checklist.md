# Delivery Checklist

## Purpose

This checklist ensures that every customer delivery is complete, consistent, and meets the agreed quality standards. It covers the full delivery lifecycle from kickoff to ongoing maintenance.

Use this checklist for every new customer engagement. Customize it to match the specific deliverables and process of your product or service.

A delivery checklist is not a substitute for judgment. It is a tool for ensuring nothing important is missed during execution.

---

## Delivery Checklist

### Phase 1 — Kickoff

- [ ] Signed agreement received and stored
- [ ] Kickoff call scheduled and completed
- [ ] Customer contacts confirmed (primary contact, technical contact, billing contact)
- [ ] Onboarding questionnaire sent and completed
- [ ] Access credentials and permissions requested
- [ ] Project timeline confirmed with customer
- [ ] Success criteria confirmed in writing
- [ ] Communication channel established (email, Slack, Teams)

---

### Phase 2 — Data Collection and Access

- [ ] All required data sources identified
- [ ] Data access granted and verified
- [ ] Data quality review completed
- [ ] Data handling agreement confirmed (if applicable)
- [ ] Sensitive data identified and handling controls applied
- [ ] Data storage location documented
- [ ] Backup and retention policy defined

---

### Phase 3 — Configuration

- [ ] System configured for this customer
- [ ] Customer-specific parameters set (domain, vocabulary, context)
- [ ] Integration connections established and tested
- [ ] Authentication and access controls configured
- [ ] Logging enabled and verified
- [ ] Error handling tested

---

### Phase 4 — Testing

- [ ] Unit testing completed for core workflow
- [ ] End-to-end workflow tested with sample data
- [ ] Output quality reviewed against defined quality criteria
- [ ] Edge cases tested (empty inputs, malformed data, long documents)
- [ ] Human review process tested
- [ ] Security controls verified
- [ ] Performance tested at expected load

---

### Phase 5 — User Training

- [ ] Training materials prepared (guide, video, documentation)
- [ ] Training session scheduled and completed
- [ ] Users have tested the system with real tasks
- [ ] Questions from training documented and answered
- [ ] Support process explained to users

---

### Phase 6 — Go-Live

- [ ] Customer approval for go-live received
- [ ] Go-live date confirmed
- [ ] Monitoring alerts configured
- [ ] First-day check-in scheduled
- [ ] First-week check-in scheduled
- [ ] Go-live announcement sent to customer team (if applicable)

---

### Phase 7 — Monitoring and Feedback

- [ ] Weekly output quality review in place for first 4 weeks
- [ ] Customer feedback collected at day 7, day 30, and day 90
- [ ] Any issues from first week documented and addressed
- [ ] Usage metrics reviewed weekly
- [ ] Feedback loop established for ongoing improvement

---

### Phase 8 — Maintenance

- [ ] Maintenance schedule defined (frequency of updates, reviews)
- [ ] Model or prompt update process documented
- [ ] Customer notification process for changes defined
- [ ] Incident response contact confirmed
- [ ] Renewal date noted in CRM or tracker

---

## Quality Gate Summary

Before going live, verify:

- [ ] All required data is available and clean
- [ ] All integrations are tested
- [ ] Human review steps are defined and staffed
- [ ] Quality criteria are documented and met in testing
- [ ] Customer has received training and confirmed readiness
- [ ] Support process is communicated and ready
